# Bash Lab — Shell и Bash с нуля

![Bash Lab](https://raw.githubusercontent.com/meeymirita/works-lab/main/images/bash.png)

Лаба по Shell и Bash: от терминала и первого скрипта до массивов, `grep`/`sed`/`awk`, `cron` и деплой-скрипта с откатом. Сквозной проект — **CoffeeOps**: набор скриптов обслуживания кофейни (заказы, отчёты, бэкап, деплой, тесты). Среда — контейнер из `bash:5` с GNU-утилитами (на macOS системный bash — 3.2).

**Статус: 🟡 методичка есть (11.10.2026), не вычитана человеком. Все команды с выводом выполнены в Docker при сборке (bash 5.3; `shellcheck` без замечаний; тесты проекта 8/8), но прохождения человеком не было. Не проверялось: интерактивный ввод, `cron` на реальном сервере, отличия macOS, установка Docker с нуля.**

## Что внутри

- **9 сессий, 53 шага, ~26 часов.** Терминал и оболочка → первый скрипт, переменные, кавычки, аргументы → ввод, условия, `case` → циклы, коды завершения, строгий режим, `trap` → функции, `getopts`, `shellcheck` → потоки, конвейеры, `xargs` → массивы и строки → `grep`, `sed`, `awk`, `jq` → `cron`, деплой-скрипт, итоговый `coffeeops.sh` с тестами.
- В каждой сессии — шаг «🔨 Сломать → починить», в сессии 9 — «Production Hell» (сломанный `deploy.sh` с пятью ошибками).
- Справка: шпаргалка, справочник ошибок (симптом → причина → что делать), глоссарий, 40 вопросов на собеседование, «что дальше».
- Режим: самостоятельная лаба, ничего проходить заранее не нужно. Docker объясняется в шаге 1.2.

## Как пересобрать методичку

Из корня сборного репозитория `anitech-performance`:

```bash
python3 tools/build-manual.py bash --run   # выполнить блоки ```bash run в Docker и собрать
python3 tools/build-manual.py bash         # собрать из сохранённых выводов (Docker не нужен)
python3 tools/build-manual.py bash --check # только проверка структуры
```

Блок кода с пометкой `bash run` выполняется в контейнере по порядку (в рамках сессии — в одной оболочке), следующий за ним блок `out auto` заполняется настоящим выводом.
