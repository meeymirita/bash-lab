## 3.1 Ввод пользователя: read | short: Ввод: read | est: ~20 мин
### intro
**Слова шага:** `read`, *стандартный ввод*, *приглашение*, *переменная REPLY*.

До сих пор скрипт получал данные только из аргументов. `read` позволяет **спросить** человека во время работы: прочитать одну строку с клавиатуры и положить в переменную.

В настоящем терминале это выглядит так (вводить в контейнере; ответ печатаешь сама):

```bash
read -p "Как тебя зовут? " name
echo "Привет, $name!"
```

**Команда по частям.** `read имя` — читать строку в переменную `имя`; ключ `-p "текст"` — показать приглашение перед вводом. Если переменных несколько, строка делится по пробелам: `read a b rest` — первое слово в `a`, второе в `b`, остаток в `rest`. Если имя не указано, ответ попадёт в переменную `REPLY`.

Другие ключи, которые пригодятся:

| Ключ | Что делает |
|---|---|
| `-r` | не обрабатывать `\` как «экран»; **всегда указывай** (shellcheck требует) |
| `-s` | не показывать ввод (пароли) |
| `-t 5` | ждать не больше 5 секунд; потом — ошибка (код больше 128) |
| `-n 1` | прочитать ровно один символ без нажатия Enter |
| `-p "…"` | приглашение |

В статьях и в этих примерах нам удобно проверять `read` без клавиатуры: подадим ответ через *here-string* `<<<` (это «подставь строку на вход команде», подробнее в сессии 6):

```bash run
read -r name <<< "Анна"
echo "Привет, $name"
read -r first rest <<< "latte большой горячий"
echo "первое: [$first], остальное: [$rest]"
read -r -t 1 late < /dev/null
echo "код при пустом вводе: $?"
```

### result
```out auto
```

Вот как выглядит настоящий интерактивный сеанс (имя «Анна» набираешь ты):

```out
Как тебя зовут? Анна
Привет, Анна!
```

### why
Без `read` скрипт не может спросить подтверждение («удалить? y/n») или попросить пароль. `-r` защищает от «съеденных» обратных слэшей, `-t` не даёт скрипту зависнуть навсегда — в автоматике (сессия 9) это важно.

### deep Как ещё можно
- Значение по умолчанию при пустом вводе: `read -r -p "Количество [1]: " qty; qty="${qty:-1}"`.
- Подтверждение одним символом: `read -r -n 1 -p "Продолжить? (y/n) " ans; echo`.
- Чтение из файла и каналов — `read` читает **со стандартного ввода**; это основа цикла `while read` (сессия 4).

### deep Если не получилось
- **Скрипт «ничего не ждёт»** — ввод идёт не с клавиатуры (запуск из `docker run` без `-it`, из `cron` или конвейера). Добавь `-it` в команду запуска контейнера.
- **В ответе пропали слэши** — забыт `-r`.

## 3.2 Арифметика и дроби | short: Арифметика | est: ~20 мин
### intro
**Слова шага:** `(( ))`, *целочисленная арифметика*, `++`, `awk` для дробей, *проверка «это число?»*.

В шаге 2.3 мы считали через `$((…))`. Есть ещё запись `(( … ))` без `$`: она **выполняет** вычисление (меняет переменные) и возвращает «истину», если результат не ноль.

```bash run
count=5
((count++))
echo "$count"
((count += 10))
echo "$count"
total=$((count * 2))
echo "$total"
(( total > 20 )) && echo "больше 20"
(( total < 20 )) || echo "не меньше 20"
```

Внутри `(( ))` переменные пишутся **без `$`**, и можно использовать привычные `+ - * / % ++ -- += < > ==`.

**Дробей в bash нет.** `180 * 1.1` — ошибка. Для дробей зовут `awk`:

```bash run
price=180
echo $((price * 11 / 10))
awk -v p="$price" 'BEGIN { printf "%.2f\n", p * 1.1 }'
awk 'BEGIN { print 7 / 2 }'
```

Первое — целочисленный обход (умножить на 11 и разделить на 10: цена с наценкой 10 %, но копейки теряются). Второе и третье — настоящие дроби через `awk` (`-v p=…` передаёт переменную внутрь, `%.2f` — два знака после запятой).

**Как проверить, что в переменной именно целое число** — регулярным выражением:

```bash run
for v in 42 -7 abc 3.5 ""; do
  if [[ "$v" =~ ^-?[0-9]+$ ]]; then echo "[$v] число"; else echo "[$v] не число"; fi
done
```

`=~` — «подходит под регулярное выражение»: `^` начало, `-?` необязательный минус, `[0-9]+` одна или несколько цифр, `$` конец. (Цикл `for` и `if` разберём в этой и следующей сессии, пока доверься результату.)

### result
```out auto
```

### why
Арифметика нужна всюду: суммы заказов, счётчики, размеры. А ограничение «только целые» — повод помнить про `awk` и не получать молча неправильные результаты. Проверка «это число?» — основа защиты скрипта от неверного ввода.

### deep Как ещё можно
- Другие системы счисления: `$((2#1010))` — двоичное, `$((0xff))` — шестнадцатеричное.
- `let "x = x + 1"` — старая запись того же, что `((x = x + 1))`.
- `bc` — калькулятор с дробями (`echo "1.1*180" | bc`), но его нет в минимальных системах; `awk` есть всегда.

### deep Если не получилось
- **`syntax error: invalid arithmetic operator`** — в выражении не число (например, `abc` или `3.5`). Проверь значения.
- **`bash: 1.1: syntax error`** — дроби в `$((…))` запрещены; используй `awk`.

## 3.3 Условия: if, test, [[ ]] | short: if и проверки | est: ~30 мин
### intro
**Слова шага:** `if`, *код завершения как истина*, `[[ ]]`, *проверка файлов*, *сравнение строк и чисел*, `&&`, `||`.

В bash «истина» — это **код завершения 0**, «ложь» — любой другой. `if` запускает команду и смотрит на её код:

```bash run
if grep -q "latte" /work/coffeeops/orders/2026-10-01.csv; then
  echo "латте заказывали"
else
  echo "латте не было"
fi
```

`grep -q` — «ищи тихо, ничего не печатай, только верни код». Если нашла — код 0 — выполняется ветка `then`. Полная форма:

```text
if команда; then
  …
elif другая_команда; then
  …
else
  …
fi
```

Чтобы проверять не программы, а условия («файл есть?», «число больше?»), есть команда `[[ … ]]` (в bash) и её старшая сестра `[ … ]`/`test` (работает в любой оболочке). Мы пишем **`[[ ]]`**: она удобнее и не требует кавычек вокруг переменных (хотя кавычки привычнее оставлять).

**Проверки файлов:**

| Выражение | Истинно, если |
|---|---|
| `-e путь` | существует |
| `-f путь` | существует и это обычный файл |
| `-d путь` | существует и это папка |
| `-r` / `-w` / `-x` | можно читать / писать / выполнять |
| `-s путь` | существует и не пуст |

```bash run
cd /work/coffeeops
[[ -f orders/2026-10-01.csv ]] && echo "файл есть"
[[ -d orders ]] && echo "папка есть"
[[ -e orders/нет.csv ]] || echo "такого файла нет"
[[ -x bin/order.sh ]] && echo "order.sh исполняемый"
```

**Строки и числа** — разные операторы:

| Что сравниваем | Запись |
|---|---|
| строки | `[[ $a == $b ]]`, `!=`, `-z "$a"` (пустая), `-n "$a"` (не пустая), `[[ $a == l* ]]` (шаблон) |
| числа | `(( a > b ))`, или `[[ $a -gt $b ]]` (`-eq -ne -lt -le -gt -ge`) |
| регулярка | `[[ $a =~ ^[0-9]+$ ]]` |
| логика | `&&` (и), `\|\|` (или), `!` (не) |

```bash run
item="latte"
qty=3
if [[ "$item" == l* && $qty -ge 2 ]]; then
  echo "латте-пара: $item x $qty"
elif [[ -z "$item" ]]; then
  echo "товар не задан"
else
  echo "обычный заказ"
fi
(( qty > 5 )) && echo "оптовый" || echo "розница"
```

Запись `команда1 && команда2` значит «вторую — только если первая успешна», `||` — «только если неуспешна». Это короткая форма `if`.

### result
```out auto
```

### why
Условия превращают список команд в программу, которая «думает»: проверяет, что файл есть, что ввод верный, что сервис отвечает. Идея «истина — это код 0» объяснит всё дальше: циклы, `set -e`, деплой.

### deep Как ещё можно
- Старая форма `[ … ]`: `[ -f "$f" ]` — пробелы **внутри скобок обязательны**, переменные — только в кавычках, `&&` нельзя (`-a`, `-o`) — поэтому пользуйся `[[ ]]`.
- `test -f файл` — то же, что `[ -f файл ]`.
- Инверсия: `if ! grep -q x файл; then …` — «если НЕ нашла».
- Сравнение с учётом/без учёта регистра: `[[ ${x,,} == yes ]]` (`,,` — в нижний регистр).

### deep Если не получилось
- **`[[: not found`** — скрипт запущен не bash (`sh script.sh`). Запускай `./script.sh` или `bash script.sh`.
- **`unexpected token 'then'`** — забыта `;` или перевод строки перед `then`.

## 3.4 case: выбор по шаблону | short: case | est: ~25 мин
### intro
**Слова шага:** `case`, *шаблон*, `;;`, `|`, `*)`, *подкоманда*.

Когда вариантов много, цепочка `elif` неудобна. `case` сравнивает значение с шаблонами сверху вниз и выполняет **первый подошедший**:

```bash run
cd /work/coffeeops
cat > bin/coffeeops.sh <<'EOF'
#!/usr/bin/env bash
# Подкоманды: start | stop | status | restart
case "${1:-}" in
  start)
    echo "запускаем CoffeeOps" ;;
  stop)
    echo "останавливаем CoffeeOps" ;;
  restart | reload)
    echo "перезапускаем CoffeeOps" ;;
  status)
    echo "работает" ;;
  "")
    echo "нужна команда: start | stop | restart | status" ;;
  *)
    echo "неизвестная команда: $1" ;;
esac
EOF
chmod +x bin/coffeeops.sh
./bin/coffeeops.sh start
./bin/coffeeops.sh reload
./bin/coffeeops.sh
./bin/coffeeops.sh fly
```

**Разбор.** `case значение in` … `esac` (это `case` наоборот); каждая ветка — `шаблон)` команды `;;` (две точки с запятой завершают ветку). Шаблоны: `start)` — точное слово; `restart | reload)` — любое из двух; `"")` — пустое значение; `*)` — «всё остальное» (ставят последним). Шаблоны такие же, как у `*.csv`: `*` любая строка, `?` один символ, `[0-9]` цифра.

```bash run
for f in report.csv notes.txt photo.JPG 7; do
  case "$f" in
    *.csv)      echo "$f — таблица" ;;
    *.txt)      echo "$f — текст" ;;
    *.jpg | *.JPG) echo "$f — картинка" ;;
    [0-9])      echo "$f — цифра" ;;
    *)          echo "$f — неизвестно" ;;
  esac
done
```

### result
```out auto
```

### why
`case` — стандартный способ разбирать подкоманды (`git commit`, `docker run`, `coffeeops start`) и расширения файлов. Читается лучше длинной цепочки `if`, а `*)` не даёт пропустить неожиданное значение.

### deep Как ещё можно
- `;&` и `;;&` — «провалиться» в следующую ветку или продолжить проверку (редко нужно).
- Включить регистронезависимость: `shopt -s nocasematch` перед `case`.

### deep Если не получилось
- **`syntax error near unexpected token ';;'`** — лишняя или пропущенная `)` у шаблона.
- **Сработала не та ветка** — порядок важен: `*)` в начале «съест» всё. Ставь `*)` последним.

## 3.5 🔨 Сломать → починить: ловушки условий | short: Сломать → починить | est: ~25 мин
### intro
:::trap Сломать → починить
Три ловушки, на которых спотыкаются даже опытные. Воспроизведи, пойми, почини.
:::

**Ошибка 1 — пустая переменная в `[ ]`:**

```bash run
cd /work/coffeeops
x=""
[ $x = a ] && echo "равно"
echo "код: $?"
```

Bash подставил пустоту, и `[ $x = a ]` превратилось в `[ = a ]` — отсюда «unary operator expected». **Почини:** кавычки `[ "$x" = a ]` или, лучше, `[[ $x == a ]]`.

**Ошибка 2 — числа как строки:**

```bash run
[[ 10 > 9 ]] && echo "10 больше 9" || echo "нет: 10 не больше 9"
(( 10 > 9 )) && echo "числа: 10 больше 9"
[[ 10 -gt 9 ]] && echo "и так тоже"
```

Внутри `[[ ]]` знак `>` сравнивает **строки по алфавиту**: `"10"` стоит раньше `"9"`, поэтому `10 > 9` ложно! **Почини:** для чисел — `(( a > b ))` или `-gt`.

**Ошибка 3 — пробелы внутри скобок:**

```bash run
a=5
[[ $a==5 ]] && echo "равно"
[[ $a == 5 ]] && echo "равно (с пробелами)"
[[$a == 5]]
```

Без пробелов вокруг `==` выражение превращается в одну непустую строку (всегда «истина»!), а без пробелов у скобок bash не понимает команду. **Правило:** `[[` и `]]` — это команды, поэтому вокруг них и вокруг операторов нужны пробелы.

### result
```out auto
```

### why
Эти три ошибки не ломают скрипт громко: условие молча срабатывает неправильно, а скрипт идёт дальше. Лучшая защита — `[[ ]]` вместо `[ ]`, `(( ))` для чисел и привычка ставить пробелы.

### deep Как ещё можно
- `shellcheck` (сессия 5) ловит большинство таких ошибок (`SC2086`, `SC2072`) ещё до запуска.
- Для проверки «пусто ли значение» удобнее всего `[[ -z "$x" ]]`.

### deep Если не получилось
- **Результат не такой, как в блоке «Ожидаемый результат»** — проверь, что используешь bash, а не `sh`: в `sh` (`dash`) команда `[[` может отсутствовать.

### quiz
- Почему `[[ 10 > 9 ]]` ложно, а `(( 10 > 9 ))` истинно?
- Чем опасно `[ $x = a ]` при пустом `x`? Как поправить двумя способами?
- Почему `[[ $a==5 ]]` всегда истинно?

:::tip Приёмка шага
Ты знаешь, как проверить число, строку и файл, и не споткнёшься на пустых значениях и пробелах.

## 3.6 Проект: калькулятор заказа | short: Калькулятор заказа | est: ~30 мин
### intro
**Слова шага:** *проверка ввода*, *код завершения 2*, *скидка*, *справка скрипта*.

Улучшим `order.sh`: цена берётся из меню по названию, ввод проверяется, при ошибке скрипт говорит понятно и завершается кодом **2** (по соглашению «неверное использование»), при 5 и более порциях действует скидка 10 %.

```bash run
cd /work/coffeeops
cat > bin/order.sh <<'EOF'
#!/usr/bin/env bash
# Использование: order.sh ТОВАР [КОЛИЧЕСТВО]
if [[ $# -lt 1 ]]; then
  echo "Использование: order.sh ТОВАР [КОЛИЧЕСТВО]"
  echo "Меню: latte espresso cappuccino americano tea"
  exit 2
fi

item="$1"
qty="${2:-1}"

if ! [[ "$qty" =~ ^[0-9]+$ ]] || (( qty < 1 )); then
  echo "Ошибка: количество должно быть целым числом больше нуля, а не '$qty'"
  exit 2
fi

case "$item" in
  latte)      price=180 ;;
  espresso)   price=120 ;;
  cappuccino) price=200 ;;
  americano)  price=140 ;;
  tea)        price=100 ;;
  *)
    echo "Ошибка: нет такого товара: '$item'"
    exit 2 ;;
esac

total=$((qty * price))
if (( qty >= 5 )); then
  total=$((total - total / 10))
  echo "Скидка 10% за $qty порций"
fi
echo "Заказ: $item x $qty = $total руб."
EOF
./bin/order.sh latte 2
./bin/order.sh tea 5
./bin/order.sh
echo "код без аргументов: $?"
./bin/order.sh latte abc
echo "код: $?"
./bin/order.sh pizza
echo "код: $?"
```

**По частям.** Первая проверка — аргументов нет вовсе → справка и `exit 2`; `qty` проверяется регулярным выражением (целое) и `(( ))` (больше нуля); `case` подбирает цену, а `*)` ловит незнакомый товар; скидка считается целочисленно: `total / 10` — десятая часть.

### result
```out auto
```

Каждая ошибка даёт понятное сообщение и код `2`, а не страшную диагностику bash.

### why
Скрипт, которому можно скормить мусор и получить осмысленный ответ, — это уже программа, а не черновик. Такая проверка аргументов «на входе» (сначала проверить, потом работать) повторится в каждом скрипте проекта.

### deep Как ещё можно
- Показать справку и при `--help`: добавь в начало `case "${1:-}" in -h|--help) … exit 0 ;; esac`. Полноценный разбор опций — `getopts` в сессии 5.
- Ошибки правильнее печатать в stderr (`echo "…" >&2`), об этом — в сессии 6.

### deep Если не получилось
- **`[[: not found`** — запущено не bash: `./bin/order.sh` использует shebang, а `sh bin/order.sh` — нет.
- **Скидка считается неверно** — `total / 10` целочисленное; для 1000 копеек и т. д. придётся перейти на `awk`.

Ты можешь: спрашивать ввод через `read` (с `-r`, `-p`, `-t`); считать целые числа и вызывать `awk` для дробей; писать `if/elif/else` с проверками файлов, строк и чисел; разбирать подкоманды `case`; проверять ввод и выходить с понятным сообщением. Неверный ввод в `order.sh` больше не ломает скрипт.
:::
