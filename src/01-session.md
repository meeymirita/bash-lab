# Сессия 1 · Терминал и оболочка
dur: ~2,5 ч

## 1.1 Терминал, оболочка, bash | short: Что такое оболочка | est: ~15 мин
### intro
**Слова шага:** *терминал*, *оболочка (shell)*, *bash*, *zsh*, *команда*.

Представь переводчика в чужой стране. Ты говоришь по-русски, система понимает только язык вызовов ядра, и между вами стоит переводчик. **Оболочка (shell)** — это и есть такой переводчик: ты печатаешь строку `ls`, оболочка находит программу `ls`, запускает её и показывает ответ.

А **терминал** — это окно, через которое ты общаешься с переводчиком: клавиатура и экран. Терминал сам ничего не понимает, он только передаёт буквы туда и обратно. Поэтому правильно говорить так: *в терминале работает оболочка*.

Оболочек много: `sh` (старейшая), **`bash`** (самая распространённая в Linux и на серверах), `zsh` (стоит по умолчанию на твоём Mac). Скрипты для серверов и автоматизации почти всегда пишут на bash — поэтому он в названии лабы.

Проверим, что у тебя на Mac. Открой приложение **Терминал** (Spotlight: [[⌘]] + [[Пробел]], набери «Терминал») и введи:

```bash
echo $SHELL
```

**Команда по частям:** `echo` — программа, которая печатает свои аргументы; `$SHELL` — *переменная окружения* (о них будет в сессии 2) с путём к твоей оболочке. Знак `$` значит «подставь значение».

Теперь узнаем версию bash, который стоит на Mac:

```bash
/bin/bash --version
```

### result
У тебя, скорее всего, так (на Mac по умолчанию zsh, а встроенный bash очень старый):

```out
/bin/zsh
GNU bash, version 3.2.57(1)-release (arm64-apple-darwin25)
Copyright (C) 2007 Free Software Foundation, Inc.
```

Главное — цифра версии: **3.2**. Ей 17 лет, в ней нет ассоциативных массивов, `mapfile` и многого другого. Поэтому дальше мы работаем не в ней.

### why
Если не различать терминал и оболочку, непонятно, почему «в одном окне команда работает, а в другом нет»: на самом деле отличается оболочка, а не окно. Версия bash на Mac (3.2) — главная причина, почему лаба идёт в контейнере: там bash 5, как на современном сервере, где потом будут жить твои скрипты.

### deep Как это выглядит внутри
Когда ты нажимаешь [[Enter]], оболочка: **1)** разбирает строку на слова; **2)** раскрывает подстановки (`$SHELL`, `*.csv`, `$(…)`); **3)** ищет программу; **4)** запускает её как новый *процесс*; **5)** ждёт, пока он закончится; **6)** запоминает его *код завершения*; **7)** снова показывает приглашение. Эти шаги мы разберём по одному в следующих сессиях.

### deep Если не получилось
- **Окно закрылось** — это нормально, оно закрывается по команде `exit`. Открой терминал заново.
- **Вместо версии bash «command not found»** — ты ввела команду не в терминале Mac, а, например, в браузерном поле. Открой приложение «Терминал».

## 1.2 Среда: Docker и образ лабы | short: Docker и образ | est: ~30 мин
### intro
**Слова шага:** *контейнер*, *образ*, *Docker*, *том (монтирование папки)*, *Dockerfile*.

**Образ** — это «слепок» компьютера: система и программы в заморозке. **Контейнер** — запущенный по образу «компьютер внутри компьютера»: у него свои файлы и программы, но он лёгкий и стартует за секунду. Удалил контейнер — всё внутри пропало, а твой Mac не тронут. Для обучения это идеально: нельзя «сломать систему».

**Docker** — программа, которая собирает образы и запускает контейнеры. Если её нет, установи **Docker Desktop** с [docker.com](https://www.docker.com/products/docker-desktop/) (выбери версию под свой процессор — Apple Silicon или Intel), запусти приложение и дождись, когда в меню сверху появится значок кита без анимации. Проверь:

```bash
docker --version
```

Дальше нужна папка на Mac для лабы. Создадим её и войдём внутрь (что значат `mkdir` и `cd` — в следующем шаге; сейчас просто набери):

```bash
mkdir -p ~/coffeeops-lab
cd ~/coffeeops-lab
```

В этой папке создай файл **`Dockerfile`** — «рецепт» образа. Пока считай следующую команду как «запиши вот этот текст в файл `Dockerfile`» (как она устроена — в сессии 6, это *here-doc*):

```bash
cat > Dockerfile <<'EOF'
FROM bash:5
RUN apk add --no-cache coreutils findutils grep sed gawk util-linux procps shellcheck jq curl diffutils
WORKDIR /work
CMD ["bash"]
EOF
```

**Рецепт по строкам:** `FROM bash:5` — взять за основу официальный образ с bash 5; `RUN apk add …` — доустановить обычные («полные») версии утилит, потому что в чистом образе они упрощённые и ведут себя чуть иначе, чем на настоящем сервере; `WORKDIR /work` — рабочая папка внутри — `/work`; `CMD ["bash"]` — по умолчанию запускать bash.

Соберём образ (один раз, пара минут):

```bash
docker build -t coffeeops-bash .
```

`build` — собрать; `-t coffeeops-bash` — дать образу имя (tag); точка `.` — «рецепт лежит в текущей папке».

Теперь запустим контейнер и войдём в него:

```bash
docker run -it --rm -v "$PWD":/work coffeeops-bash
```

**Команда по частям:** `run` — создать и запустить контейнер; `-it` — подключить к нему клавиатуру и экран (интерактивный терминал); `--rm` — удалить контейнер при выходе; `-v "$PWD":/work` — *том*: показать папку, в которой ты стоишь (`$PWD`, «где я»), внутри контейнера как `/work`; `coffeeops-bash` — имя образа.

Приглашение изменится на что-то вроде `bash-5.3#`. Это уже контейнер. Проверим версию:

```bash run hidden
touch /work/Dockerfile
```

```bash run
echo $BASH_VERSION
```

### result
Внутри контейнера (последняя цифра версии может отличаться):

```out auto
```

И проверка папки: создай файл в контейнере — он сразу появится на Mac.

```bash run
touch /work/привет.txt
ls /work
```

```out auto
```

Открой папку `~/coffeeops-lab` в Finder — там лежит `привет.txt`. Выйти из контейнера: команда `exit` или [[Ctrl]]+[[D]]. Вернуться — той же командой `docker run …` из папки `~/coffeeops-lab`.

### why
Почти все тонкости Bash (массивы, `mapfile`, поведение `sed -i`) зависят от версии и от набора утилит. Единая среда делает так, что всё в лабе работает у тебя ровно так, как написано. Docker тебе пригодится дальше (Docker-лаба) — это первое знакомство.

### deep Как ещё можно
- **Linux на самом компьютере или WSL** (Windows) — если у тебя уже есть Linux с bash 5, Docker не нужен: работай в папке `~/coffeeops-lab` прямо там и вместо `/work` читай «эта папка».
- **Виртуальная машина** (UTM, VirtualBox) — тяжелее, но тоже годится.
- **Поставить bash 5 на Mac** (`brew install bash`) — получишь тот же bash, но не те утилиты: `sed`, `grep`, `ls` на Mac — версии BSD, и в сессии 8 мы увидим, чем они отличаются. Контейнер избавляет от этих сюрпризов.

### deep Если не получилось
- **`Cannot connect to the Docker daemon`** — приложение Docker Desktop не запущено. Открой его и подожди значок кита.
- **`docker: command not found`** — Docker не установлен или терминал открыт до установки. Закрой терминал и открой заново.
- **Сборка зависла на `apk add`** — нет интернета или он медленный; повтори `docker build`.
- **В контейнере `/work` пустая** — ты запустила `docker run` не из папки `~/coffeeops-lab`. Выйди (`exit`), перейди в неё (`cd ~/coffeeops-lab`) и запусти заново.

## 1.3 Навигация: где я и как ходить | short: Навигация | est: ~25 мин
### intro
**Слова шага:** *текущая папка*, *путь*, *абсолютный и относительный путь*, *домашняя папка*, `pwd`, `ls`, `cd`.

Файловая система — дерево папок. Корень дерева — `/`. Ты в каждый момент «стоишь» в какой-то папке, и от неё считаются *относительные* пути. Войди в контейнер (шаг 1.2) и узнай, где ты:

```bash run hidden
touch Dockerfile привет.txt
```

```bash run
pwd
```

`pwd` — *print working directory*. Посмотрим, что в папке (у тебя это `Dockerfile` и `привет.txt` из прошлого шага):

```bash run
ls
```

Создадим структуру для практики:

```bash run
mkdir -p demo/a/b
cd demo
pwd
ls
```

**Команда по частям.** `mkdir` — создать папку; ключ `-p` — «создай всю цепочку и не ругайся, если уже есть». `cd demo` — *change directory*, войти в папку `demo`. Путь `demo` без `/` в начале — *относительный*: от текущей папки.

Пути бывают двух видов, и в них есть специальные имена:

| Запись | Значит |
|---|---|
| `/work/demo` | **абсолютный** путь: от корня, не зависит от того, где ты стоишь |
| `a/b` | **относительный**: от текущей папки |
| `.` | текущая папка |
| `..` | папка выше |
| `~` | домашняя папка пользователя (в контейнере `/root`) |
| `-` | предыдущая папка (только для `cd`) |

```bash run
cd a/b
pwd
cd ..
pwd
cd ../..
pwd
cd ~
pwd
cd -
pwd
```

Теперь `ls` с ключами. Каждый ключ — буква после дефиса; их можно склеивать (`-la` = `-l -a`):

```bash run
cd /work/demo
touch .скрытый файл1.txt
ls
ls -a
ls -l
ls -lh
```

### result
Выводы команд подряд (даты и владелец у тебя другие):

```out auto
```

Что значат ключи: `-a` (*all*) — показать и скрытые файлы (имя начинается с точки); `-l` (*long*) — длинный формат с правами, владельцем, размером, датой; `-h` (*human*) — размеры в КБ/МБ, а не в байтах; `-t` — сортировка по времени (новые сверху). Столбцы длинного формата разберём в шаге 1.5.

### why
Все команды дальше принимают пути. Если путать абсолютный и относительный, скрипт будет работать «у тебя в папке», а на сервере — нет: это самая частая причина «у меня работало».

### deep Как ещё можно
- Автодополнение: набери начало имени и нажми [[Tab]] — оболочка допишет, а два раза [[Tab]] покажет варианты.
- История: стрелка вверх возвращает прошлые команды; [[Ctrl]]+[[R]] ищет по истории.
- `ls /work/demo/a` — посмотреть другую папку, не заходя в неё; `ls -d */` — только папки.

### deep Если не получилось
- **`No such file or directory`** — такого пути нет. Проверь `pwd` и опечатки; регистр важен (`Demo` ≠ `demo`).
- **`cd: too many arguments`** — в имени папки пробел, а ты его не защитила. Напиши в кавычках: `cd "моя папка"`.

## 1.4 Файлы: создать, скопировать, прочитать, удалить | short: Файлы | est: ~30 мин
### intro
**Слова шага:** `touch`, `cp`, `mv`, `rm`, `cat`, `head`, `tail`, `wc`, *шаблон `*`*.

Работаем в папке `demo`. Создаём файлы и пишем в них текст (`echo "текст" > файл` — «запиши в файл»; подробности — в сессии 6):

```bash run
cd /work/demo
echo "latte 180" > menu.txt
echo "espresso 120" >> menu.txt
echo "tea 100" >> menu.txt
cat menu.txt
```

`>` создаёт файл заново (старое содержимое пропадает!), `>>` дописывает в конец. `cat` печатает файл целиком.

Читаем по частям и считаем:

```bash run
head -n 2 menu.txt
tail -n 1 menu.txt
wc -l menu.txt
wc -w menu.txt
```

`head` — первые строки, `tail` — последние, `wc` — *word count*: `-l` строки, `-w` слова, `-c` байты.

Копируем, переносим, удаляем:

```bash run
cp menu.txt menu.bak
mv menu.bak a/menu.old
ls -R
rm a/menu.old
ls a
```

**Команда по частям.** `cp что куда` — копия; `mv что куда` — перенос (и переименование: `mv a b` в той же папке); `rm` — удалить; `ls -R` — показать вложенные папки. `rm` **не отправляет в корзину**: файл пропадает насовсем.

Шаблон `*` заменяет «любое количество любых символов». Его раскрывает оболочка **до** запуска команды:

```bash run
touch a.csv b.csv c.csv
ls *.csv
echo *.csv
echo *.xml
```

Целая папка удаляется только с ключом `-r` (*recursive*): `rm -r a`. А `rm -rf` (`-f` — *force*, без вопросов и ошибок) удаляет всё без подтверждения, поэтому **перед `rm -rf` всегда выполняй ту же команду с `ls` или `echo`**.

### result
```out auto
```

В конце: `echo *.xml` напечатал саму звёздочку — файлов `.xml` нет, и оболочка оставила шаблон как есть. Запомни этот эффект, он ещё встретится.

### why
Эти десять команд — 90 % повседневной работы в терминале. А `*` — первый пример того, что **оболочка делает работу до команды**: `ls` в `ls *.csv` видит не звёздочку, а готовый список файлов. Это объясняет множество странных эффектов дальше.

### deep Как ещё можно
- `touch` у существующего файла просто обновляет время изменения.
- `cp -r папка копия` копирует папку целиком; `mv` папки ключа не требует.
- `rm -i` спрашивает подтверждение у каждого файла.
- `less файл` — листать длинный файл ([[q]] — выход). Если его нет в контейнере, хватит `head`, `tail` и `cat`.

### deep Если не получилось
- **`cp: cannot stat 'x': No such file or directory`** — файла `x` нет в этой папке; сверь `pwd` и `ls`.
- **`rm: cannot remove 'a': Is a directory`** — для папки нужен ключ `-r`.

## 1.5 Права, владелец и справка | short: Права и справка | est: ~30 мин
### intro
**Слова шага:** *владелец*, *группа*, *права `rwx`*, `chmod`, `--help`, `type`, `help`.

В длинном выводе `ls -l` каждая строка выглядит так:

```text
-rw-r--r-- 1 root root 22 Oct 11 12:00 menu.txt
```

Читаем слева направо:

| Колонка | Пример | Значит |
|---|---|---|
| тип и права | `-rw-r--r--` | первый символ: `-` файл, `d` папка; дальше три тройки: владелец, группа, остальные |
| ссылки | `1` | число жёстких ссылок (пока не важно) |
| владелец | `root` | кто хозяин |
| группа | `root` | какая группа |
| размер | `22` | в байтах |
| дата | `Oct 11 12:00` | когда менялся |
| имя | `menu.txt` | имя файла |

В каждой тройке: `r` — читать, `w` — писать, `x` — выполнять (для папки: входить). Прочерк — права нет. Значит `-rw-r--r--` = владелец читает и пишет; группа и остальные только читают.

Права меняет `chmod`. Два способа записи:

```bash run
cd /work/demo
touch run.sh
ls -l run.sh
chmod +x run.sh
ls -l run.sh
chmod u-x,g+w run.sh
ls -l run.sh
chmod 640 run.sh
ls -l run.sh
```

**Буквами:** `u` владелец, `g` группа, `o` остальные, `a` все; `+` добавить, `-` убрать, `=` задать точно. **Цифрами:** `r=4`, `w=2`, `x=1`, суммируем в каждой тройке: `6`=`rw-`, `4`=`r--`, `0`=`---`. `640` = владелец `rw-`, группа `r--`, остальные ничего.

Как узнать, что делает незнакомая команда? Четыре способа:

```bash run
ls --help | head -n 5
type cd
type ls
help cd | head -n 3
command -v bash
```

**Команда по частям.** `команда --help` — краткая справка (у большинства утилит); `type имя` — что это: встроенная команда оболочки (`cd`, `echo`), программа, функция или алиас; `help имя` — справка по встроенной (у `cd` нет файла программы, поэтому `--help` не работает); `command -v` — где лежит. Для программ ещё есть `man имя`: на Mac он работает, в нашем контейнере справочных страниц нет — там пользуйся `--help`.

### result
```out auto
```

### why
Права — самая частая причина ошибок при запуске скриптов (`Permission denied`), а справка — единственный способ не гуглить каждый ключ. Различие «встроенная команда / программа» объясняет, почему у `cd` нет `--help`.

### deep Как ещё можно
- Права на папки: `x` позволяет войти внутрь, `r` — увидеть список, `w` — создавать и удалять внутри.
- `umask` — какие права получают новые файлы по умолчанию (обычно `022`: у файла `644`, у папки `755`).
- Менять владельца — `chown`, нужны права root; в контейнере мы работаем под root, поэтому ограничений почти нет.

### deep Если не получилось
- **`chmod: cannot access`** — нет такого файла; сверь `ls`.
- **Права «не меняются» на примонтированной папке с Mac** — Docker Desktop отображает права файлов с Mac условно. Упражнения в папке `demo` тоже лежат в этом томе; если права не меняются, повтори те же команды в `/tmp` внутри контейнера (там обычная файловая система).

### quiz

## 1.6 🔨 Сломать → починить: permission denied и command not found | short: Сломать → починить | est: ~25 мин
### intro
:::trap Сломать → починить
Две самые частые ошибки новичка. Воспроизведи их и почини. Затем соберём проект CoffeeOps.
:::

**Ошибка 1 — `Permission denied`.** Создадим «скрипт» и попробуем запустить:

```bash run
cd /work/demo
echo 'echo привет' > hello.sh
./hello.sh
```

Файл есть, но у него нет права `x`. **Почини** (одна команда из шага 1.5) и запусти снова:

```bash run
chmod +x hello.sh
./hello.sh
```

**Ошибка 2 — `command not found`.** Введём несуществующую команду и «команду» без пути:

```bash run
leatte
hello.sh
echo $PATH
```

`hello.sh` лежит в текущей папке, но оболочка ищет команды только в папках из `PATH` (список через двоеточие), а текущей папки там нет — из соображений безопасности. Поэтому нужен путь: `./hello.sh` (`./` — «из текущей папки»). **Почини** тремя способами:

```bash run
./hello.sh
bash hello.sh
PATH="$PATH:." hello.sh
```

**Теперь собираем проект.** Создадим структуру CoffeeOps и данные (дальше сессии работают с ними). Папки:

```bash run
cd /work
mkdir -p coffeeops/bin coffeeops/lib coffeeops/orders coffeeops/logs coffeeops/backup
cd coffeeops
ls
```

Данные создаёт небольшой скрипт-генератор. Разбирать его не нужно: через пару сессий ты прочитаешь его без труда. Пока: «записать этот текст в файл `seed.sh` и запустить».

```bash run
cat > seed.sh <<'EOF'
#!/usr/bin/env bash
# Генератор тестовых данных CoffeeOps: три файла заказов и один лог
for day in 01 02 03; do
  awk -v day="$day" 'BEGIN {
    n = split("latte:180 espresso:120 cappuccino:200 americano:140 tea:100", m, " ")
    print "time,item,qty,price"
    for (i = 1; i <= 12; i++) {
      split(m[(i * 3 + day) % n + 1], p, ":")
      printf "%02d:%02d,%s,%d,%d\n", 8 + int(i / 2), (i * 7) % 60, p[1], (i + day) % 3 + 1, p[2]
    }
  }' > "orders/2026-10-$day.csv"
done
awk 'BEGIN {
  split("INFO INFO INFO WARN INFO ERROR INFO INFO", lv, " ")
  split("order-created payment-ok printer-slow db-timeout order-created stock-low", ms, " ")
  for (i = 1; i <= 40; i++)
    printf "2026-10-01 %02d:%02d:%02d %s %s id=%d\n", 8 + int(i / 5), (i * 11) % 60, (i * 17) % 60, lv[i % 8 + 1], ms[i % 6 + 1], 100 + i
}' > logs/app.log
EOF
bash seed.sh
ls orders logs
head -n 4 orders/2026-10-01.csv
```

### result
```out auto
```

Первая ошибка: `Permission denied` (нет права `x`) — после `chmod +x` скрипт печатает «привет». Вторая: `command not found` — оболочка не нашла команду в `PATH`. Последний блок создаёт проект: папки, три файла заказов `orders/*.csv` и лог `logs/app.log`.

### why
Эти два сообщения встречаются каждый день. Научившись читать их, ты чинишь 80 % проблем с запуском за минуту. И теперь у проекта есть данные для следующих сессий.

### deep Как ещё можно
- Ошибка «No such file or directory» при запуске скрипта, хотя файл есть, — обычно в первой строке `#!` указан интерпретатор, которого нет. Мы пишем `#!/usr/bin/env bash` — это ищет bash в `PATH`.
- `command -v` показывает, какой именно файл запустится по имени команды.

### deep Если не получилось
- **`awk: not found`** — образ собран без `gawk`; пересобери: `docker build -t coffeeops-bash .` из папки с `Dockerfile`.
- **Файлы в `orders/` пустые** — скрипт запущен не из папки `coffeeops`. Выполни `cd /work/coffeeops` и повтори `bash seed.sh`.
