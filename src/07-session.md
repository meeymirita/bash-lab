## 7.1 Индексные массивы | short: Массивы | est: ~30 мин
### intro
**Слова шага:** *массив*, *индекс*, `${a[@]}`, `${#a[@]}`, `+=`, *срез*.

**Массив** — переменная, в которой лежит **список** значений. Каждый элемент имеет номер (индекс), счёт идёт **с нуля**.

```bash run
drinks=(latte espresso tea)
echo "первый: ${drinks[0]}"
echo "третий: ${drinks[2]}"
echo "все: ${drinks[@]}"
echo "сколько: ${#drinks[@]}"
echo "номера: ${!drinks[@]}"
```

**По частям.** `drinks=(…)` — создать массив (элементы через пробел); `${drinks[0]}` — элемент по номеру (**фигурные скобки обязательны**); `${drinks[@]}` — все элементы; `${#drinks[@]}` — их количество; `${!drinks[@]}` — список индексов.

**Добавить, изменить, удалить:**

```bash run
drinks+=(cappuccino)
drinks[1]="doppio"
echo "${drinks[@]}"
unset 'drinks[0]'
echo "после unset: ${drinks[@]} (индексы: ${!drinks[@]})"
copy=("${drinks[@]}")
echo "копия: ${copy[@]}"
```

`+=(…)` — дописать в конец; `drinks[1]=…` — заменить; `unset 'drinks[0]'` — удалить элемент (индексы **не перенумеровываются**, получается «дырка»); `copy=("${drinks[@]}")` — копия массива (кавычки обязательны).

**Срезы и перебор:**

```bash run
nums=(10 20 30 40 50)
echo "со 2-го, два элемента: ${nums[@]:1:2}"
echo "последние два: ${nums[@]: -2}"
for n in "${nums[@]}"; do
  echo -n "[$n] "
done
echo
```

**Главное: `"${a[@]}"` в кавычках.** Так каждый элемент остаётся отдельным словом, даже если в нём есть пробелы (как `"$@"` для аргументов). А `"${a[*]}"` склеивает всё в одну строку (первым символом `IFS`):

```bash run
items=("iced latte" tea "cold brew")
printf '[%s] ' "${items[@]}"; echo
printf '[%s] ' "${items[*]}"; echo
printf '[%s] ' ${items[@]}; echo
```

**Передача массива в функцию** — как список аргументов:

```bash run
count_items() {
  echo "получено: $#"
}
count_items "${items[@]}"
```

### result
```out auto
```

Видно, что `"${items[@]}"` сохранил три элемента, `"${items[*]}"` склеил в один, а без кавычек `iced latte` рассыпался на два слова.

### why
Массивы — правильный способ хранить списки (файлы, серверы, товары) без «строк с пробелами», которые разбираются по кавычкам и ломаются. Вместе с `"${a[@]}"` они делают скрипты надёжнее.

### deep Как ещё можно
- `declare -a имя` — явно объявить индексный массив; `declare -p имя` покажет его содержимое.
- Присвоить сразу по индексам: `a=([0]=x [5]=y)` — массив с «дырками».
- `${a[-1]}` — последний элемент (bash 4.3+; в bash 3.2 на Mac не работает — ещё один повод для контейнера).

### deep Если не получилось
- **`echo $drinks` печатает только первый элемент** — без индекса это то же, что `${drinks[0]}`. Все элементы — `"${drinks[@]}"`.
- **`bad substitution`** — забыты фигурные скобки или кавычки у `unset 'a[0]'`.

## 7.2 Сортировка, поиск и чтение в массив | short: Сортировка и mapfile | est: ~30 мин
### intro
**Слова шага:** `mapfile`, *сортировка*, *уникальные*, *поиск по массиву*, `IFS`.

В bash нет встроенной сортировки массива — её делают внешней командой `sort`, а результат читают обратно командой `mapfile` (синоним `readarray`; **нужен bash 4+**, на Mac это недоступно):

```bash run
cd /work/coffeeops
mapfile -t items < <(cut -d, -f2 orders/*.csv | grep -v '^item$')
echo "всего позиций: ${#items[@]}"
mapfile -t sorted < <(printf '%s\n' "${items[@]}" | sort -u)
echo "уникальные: ${sorted[@]}"
```

**По частям.** `mapfile -t имя` читает строки со `stdin` в массив (по строке на элемент, `-t` убирает символ конца строки); `< <(…)` — подстановка процесса (шаг 6.4); `printf '%s\n' "${a[@]}"` печатает элементы по одному на строку — вход для `sort`.

**Поиск элемента в массиве** — циклом:

```bash run
contains() {
  local needle="$1"; shift
  local x
  for x in "$@"; do
    [[ "$x" == "$needle" ]] && return 0
  done
  return 1
}
contains tea "${sorted[@]}" && echo "tea есть"
contains pizza "${sorted[@]}" || echo "pizza нет"
```

Функция берёт искомое из `$1`, делает `shift`, и по остальным аргументам (элементы массива) идёт циклом.

**Склеить массив в строку** с разделителем — через `IFS` в подоболочке:

```bash run
join_by() { local IFS="$1"; shift; echo "$*"; }
join_by , "${sorted[@]}"
join_by ' | ' "${sorted[@]}"
```

Здесь `local IFS` временно меняет разделитель, а `"$*"` склеивает аргументы этим разделителем.

### result
```out auto
```

### why
`mapfile` и `printf '%s\n' "${a[@]}"` — стандартная пара для «записать вывод команды в массив» и «отдать массив команде»: так сортируют, фильтруют и убирают дубли. Без `mapfile` пришлось бы разбирать строки руками.

### deep Как ещё можно
- `readarray -t` — то же самое, другое имя.
- В bash 3.2 (Mac) `mapfile` нет: пишут `while read -r x; do a+=("$x"); done < <(…)` — работает везде, но длиннее.
- `${a[@]/шаблон/замена}` — заменить в каждом элементе.
- Если элементов много, `sort | uniq` быстрее, чем перебор в bash.

### deep Если не получилось
- **`mapfile: command not found`** — используется bash < 4. Проверь `echo $BASH_VERSION` в своём контейнере.
- **Пустой массив** — команда внутри `< <(…)` ничего не вернула; запусти её отдельно.

## 7.3 Ассоциативные массивы | short: Ассоциативные массивы | est: ~30 мин
### intro
**Слова шага:** *ассоциативный массив*, *ключ*, `declare -A`, *счётчик*, `${!m[@]}`.

В индексном массиве доступ по номеру, а в **ассоциативном** — по **ключу** (строке): как словарь или таблица «название → цена». Такие массивы **требуют bash 4+** и объявляются явно через `declare -A`:

```bash run
declare -A price=([latte]=180 [espresso]=120 [tea]=100)
price[cappuccino]=200
echo "латте: ${price[latte]}"
echo "ключи: ${!price[@]}"
echo "значения: ${price[@]}"
echo "сколько: ${#price[@]}"
```

**Перебор по ключам** (порядок ключей **не гарантирован** — для вывода сортируй):

```bash run
for k in "${!price[@]}"; do
  echo "$k => ${price[$k]}"
done | sort
```

**Проверка наличия ключа и удаление:**

```bash run
[[ -v price[tea] ]] && echo "tea в меню"
[[ -v price[pizza] ]] || echo "pizza нет в меню"
unset 'price[tea]'
echo "после удаления: ${#price[@]} позиций"
```

**Счётчики** — самое частое применение: «сколько раз встретилось каждое слово».

```bash run
declare -A count=()
for w in latte tea latte espresso latte tea; do
  count[$w]=$(( ${count[$w]:-0} + 1 ))
done
for k in "${!count[@]}"; do
  echo "$k: ${count[$k]}"
done | sort
```

`${count[$w]:-0}` — «значение по ключу, а если ключа ещё нет — 0» (привычная нам форма `:-`, как у аргументов). Так счётчик заводится сам при первой встрече ключа.

### result
```out auto
```

### why
Ассоциативные массивы заменяют длинные `case` и повторные проходы по данным: «название → цена», «сервер → адрес», «слово → частота». Счётчик по ключам решает множество задач без единой внешней команды.

### deep Как ещё можно
- Из файла «ключ=значение» можно заполнять массив циклом `while IFS== read -r k v; do m[$k]=$v; done < файл`.
- Вложенных массивов в bash нет; для составных значений используют ключи вида `a,b` или несколько массивов.
- `declare -p price` покажет содержимое с ключами — удобно при отладке.

### deep Если не получилось
- **`declare: -A: invalid option`** — bash 3.2 (Mac) не знает `-A`. Запусти в контейнере.
- **Ключ с пробелом не находится** — ключ-строку берут в кавычки: `price["iced latte"]=200`.
- **Ассоциативный массив «в виде индексного»** — забыто `declare -A`: ключи превращаются в нули (`price[latte]` и `price[tea]` указывают на один элемент `0`).

## 7.4 Строки: расширения параметров | short: Операции со строками | est: ~30 мин
### intro
**Слова шага:** *расширение параметра*, `${#x}`, `${x#…}`, `${x%…}`, `${x/…/…}`, *регистр*, *срез*.

Для работы со строками не нужны внешние команды: форма `${переменная…}` умеет многое.

```bash run
file="/work/coffeeops/orders/2026-10-01.csv"
echo "длина: ${#file}"
echo "имя файла:  ${file##*/}"
echo "папка:      ${file%/*}"
echo "без .csv:   ${file%.csv}"
echo "расширение: ${file##*.}"
```

**Запоминалка: `#` режет с начала, `%` — с конца.** Один знак — **самое короткое** совпадение, два — **самое длинное**:

| Запись | Что делает | Пример результата |
|---|---|---|
| `${x#шаблон}` | убрать самое короткое совпадение с **начала** | `${file#*/}` → `work/coffeeops/...` |
| `${x##шаблон}` | убрать самое длинное с начала | `${file##*/}` → `2026-10-01.csv` |
| `${x%шаблон}` | убрать самое короткое с **конца** | `${file%.csv}` → без расширения |
| `${x%%шаблон}` | убрать самое длинное с конца | `${file%%/*}` → пусто |

**Замена, регистр, срезы:**

```bash run
name="2026-10-01"
echo "первая замена:   ${name/-/_}"
echo "все замены:      ${name//-/_}"
word="Latte"
echo "ВЕРХНИЙ:  ${word^^}"
echo "нижний:   ${word,,}"
low="espresso"
echo "первая заглавная: ${low^}"
echo "срез 0..4:       ${name:0:4}"
echo "с 5-го знака:    ${name:5}"
echo "последние 2:     ${name: -2}"
empty=""
echo "пусто, значение по умолчанию: ${empty:-нет данных}"
```

`${x/шаблон/замена}` — заменить первое вхождение, `${x//шаблон/замена}` — все; `^^` и `,,` — в верхний и нижний регистр (bash 4+); `${x:начало:длина}` — подстрока (отсчёт с нуля; перед отрицательным числом нужен пробел).

Применим к настоящей задаче — день из имени файла и переименование:

```bash run
cd /work/coffeeops
for f in orders/*.csv; do
  base="${f##*/}"
  day="${base%.csv}"
  echo "файл $base — день ${day##*-}, месяц ${day:5:2}"
done
```

### result
```out auto
```

### why
`${…}` заменяет вызовы `basename`, `dirname`, `cut`, `sed` и `tr` там, где задачи простые, и работает быстрее (внешняя команда — это новый процесс). Это основной инструмент для работы с путями и именами.

### deep Как ещё можно
- `basename` и `dirname` делают то же, что `${f##*/}` и `${f%/*}`, но с меньшей магией; выбирай по читаемости.
- `${x:?сообщение}` и `${x:-значение}`, `${x:=значение}` (присвоить значение по умолчанию) — те же расширения, что мы видели для аргументов.
- Для сложных замен (регулярки) бери `sed` (сессия 8).

### deep Если не получилось
- **`bad substitution`** — опечатка в скобках или в шаблоне, или bash < 4 (`^^`, `,,`).
- **Пусто там, где ждёшь результат** — шаблон не совпал с содержимым; проверь `echo "$x"`.

## 7.5 🔨 Сломать → починить: потерянные элементы | short: Сломать → починить | est: ~20 мин
### intro
:::trap Сломать → починить
Массивы «сжимаются» и «рассыпаются», когда забыты кавычки или способ создания неверен. Воспроизведи и почини.
:::

**Ошибка 1 — «массив из одного элемента»:**

```bash run
cd /work/coffeeops
files=$(ls orders)
echo "элементов: ${#files[@]}"
```

`files=$(…)` — это **строка**, а не массив: в ней три имени, но элемент один. **Почини:** шаблон, а не вывод `ls`:

```bash run
files=(orders/*.csv)
echo "элементов: ${#files[@]}"
```

**Ошибка 2 — элементы с пробелами рассыпались:**

```bash run
list=("iced latte" "cold brew")
for x in ${list[@]}; do echo "[$x]"; done
echo "--- в кавычках:"
for x in "${list[@]}"; do echo "[$x]"; done
```

**Ошибка 3 — только первый элемент:**

```bash run
nums=(1 2 3)
echo "$nums"
echo "${nums[@]}"
```

`$nums` без индекса — всегда `${nums[0]}`.

**Ошибка 4 — ассоциативный массив без `declare -A`:**

```bash run
menu[latte]=180
menu[tea]=100
echo "латте: ${menu[latte]}"
echo "ключи: ${!menu[@]}"
```

Без объявления bash считает массив индексным: `latte` и `tea` как индексы превращаются в `0`, второе значение затирает первое — «латте» стоит 100, а ключ один. **Почини:** `declare -A menu` до первого присваивания.

### result
```out auto
```

### why
Все четыре ошибки дают «почти правильный» результат, и поэтому их трудно заметить. Если обращаться ко всем элементам через `"${a[@]}"`, создавать массив через `(…)` или `mapfile`, а ассоциативный объявлять — они не повторятся.

### deep Как ещё можно
- `shellcheck` отмечает эти ошибки (`SC2086`, `SC2206`, `SC2128`): запускай его на каждом скрипте.
- Диагностика: `declare -p имя` покажет, что на самом деле лежит в переменной.

### deep Если не получилось
- **В блоке 4 ключи другие** — у тебя уже объявлен ассоциативный массив с таким именем (например, `price` из шага 7.3): возьми новое имя или выполни `unset имя`.

- Почему `files=$(ls)` не делает массив?
- Что напечатает `echo "$arr"` для массива?
- Что случится, если не объявить `declare -A`?

## 7.6 Проект: счётчик заказов по товарам | short: Проект: счётчик | est: ~30 мин
### intro
**Слова шага:** *счётчик на ассоциативном массиве*, *чтение CSV*, *printf-таблица*.

Задача из приёмки: **посчитать заказы по товарам без внешних утилит** (подсчёт — на чистом bash; сортировку для вывода допустимо отдать `sort`, это уже оформление). Скрипт читает все CSV построчно, суммирует количество и выручку по каждому товару.

```bash run
cd /work/coffeeops
cat > bin/count.sh <<'EOF'
#!/usr/bin/env bash
# Заказы по товарам: порций и выручка. Использование: count.sh [ПАПКА]
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
# shellcheck source=../lib/common.sh
source "$ROOT/lib/common.sh"

dir="${1:-$ROOT/orders}"
[[ -d "$dir" ]] || die "нет папки '$dir'" 2

declare -A qty_by=() sum_by=()
for f in "$dir"/*.csv; do
  [[ -e "$f" ]] || continue
  while IFS=, read -r _ item qty price; do
    [[ "$item" == "item" ]] && continue
    qty_by[$item]=$(( ${qty_by[$item]:-0} + qty ))
    sum_by[$item]=$(( ${sum_by[$item]:-0} + qty * price ))
  done < "$f"
done

printf '%-12s %8s %10s\n' ITEM QTY SUM
for item in "${!qty_by[@]}"; do
  printf '%-12s %8d %10d\n' "$item" "${qty_by[$item]}" "${sum_by[$item]}"
done | sort -k3 -rn
EOF
chmod +x bin/count.sh
./bin/count.sh
shellcheck bin/count.sh && echo "shellcheck: чисто"
```

**По частям.** `declare -A … =()` — два счётчика: порции и выручка; `read -r _ item qty price` — четыре поля строки (первое — время — отбрасываем в «пустую» переменную `_`); заголовок пропускаем; в цикле счётчики увеличиваются арифметикой `$((…))`; `printf '%-12s %8d'` печатает выровненные столбцы (`%-12s` — строка шириной 12, прижатая влево; `%8d` — число шириной 8); конвейер с `sort -k3 -rn` — сортировка по выручке (3-му столбцу) по убыванию. Заголовок печатается до конвейера, поэтому в сортировку не попадает.

### result
```out auto
```

### why
Скрипт читает данные и считает их сам, без цепочки `cut | sort | uniq | awk`. Для небольших данных так проще понимать и поддерживать, а структура «ассоциативный массив + цикл» подходит для десятков похожих задач.

### deep Как ещё можно
- Те же числа получаются одной командой `awk` (сессия 8) — она быстрее на больших файлах; bash хорош для логики вокруг, а не для обработки миллионов строк.
- Вывод в CSV: замени `printf` формат на `'%s,%d,%d\n'`.

### deep Если не получилось
- **`unbound variable`** — при `set -u` забыт `${…:-0}` у счётчика.
- **Столбцы «поехали»** — в тексте кириллица: `printf` считает ширину в байтах, а не в буквах. Поэтому заголовок мы написали латиницей; для русского выравнивай через `awk` или `column`.

Ты можешь: создавать, изменять, копировать, срезать индексные массивы и передавать их в функции; сортировать и искать через `sort`, `mapfile`; пользоваться ассоциативными массивами как словарём и счётчиком; резать и менять строки через `${…}`. `count.sh` считает заказы по товарам без внешних утилит.
:::
