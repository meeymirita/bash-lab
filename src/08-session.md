## 8.1 Регулярные выражения | short: Регулярные выражения | est: ~30 мин
### intro
**Слова шага:** *регулярное выражение (regex)*, *шаблон*, *символьный класс*, *якорь*, *квантификатор*, *BRE и ERE*.

**Регулярное выражение** — шаблон для поиска текста: «слово ERROR в начале строки», «три цифры подряд», «адрес вида id=число». Это не язык bash, а общий инструмент: его понимают `grep`, `sed`, `awk`, `[[ =~ ]]`, редакторы и почти все языки.

Рабочий файл — наш журнал `logs/app.log`. Посмотрим, как он выглядит:

```bash run
cd /work/coffeeops
head -n 4 logs/app.log
wc -l < logs/app.log
```

Строки вида `дата время УРОВЕНЬ событие id=номер`. Основные элементы шаблонов:

| Запись | Что значит | Пример |
|---|---|---|
| `abc` | буквы как есть | `ERROR` |
| `.` | любой один символ | `id=1.1` |
| `^` / `$` | начало / конец строки | `^2026` |
| `[abc]`, `[0-9]`, `[a-z]` | один символ из набора | `[0-9]` |
| `[^abc]` | один символ **не** из набора | `[^ ]` (не пробел) |
| `*` | предыдущее — 0 или больше раз | `ab*` |
| `+` | 1 или больше (в ERE) | `[0-9]+` |
| `?` | 0 или 1 (в ERE) | `colou?r` |
| `{n,m}` | от n до m раз (в ERE) | `[0-9]{2}` |
| `\|` | «или» (в ERE) | `ERROR\|WARN` |
| `( )` | группа (в ERE) | `(ab)+` |
| `\` | отменить особый смысл | `\.` — именно точка |

**BRE и ERE.** В «базовых» регулярках (**BRE**, по умолчанию в `grep` и `sed`) символы `+ ? | ( ) { }` **буквальные**, а особыми их делает обратный слэш (`\+`, `\|`). В «расширенных» (**ERE**, ключ `-E`) они особые сразу. Читать и писать ERE проще, поэтому мы будем использовать **`grep -E`** и **`sed -E`**.

Проверим на практике (`grep -E` печатает строки, подходящие под шаблон):

```bash run
grep -E '^2026-10-01 08' logs/app.log | head -n 3
grep -E 'ERROR|WARN' logs/app.log | head -n 3
grep -E 'id=1[0-9]{2}$' logs/app.log | head -n 3
grep -E ' (INFO|WARN) printer' logs/app.log | head -n 2
```

### result
```out auto
```

### why
Без регулярок поиск и замена в тексте — перебор вручную. С ними одна строка находит «все ошибки в первый час» или «все строки с таким-то форматом». Умение читать регулярку важно и само по себе: чужие скрипты полны ими.

### deep Как ещё можно
- Группы `( )` запоминают найденное: на них потом ссылаются `\1`, `\2` в `sed` (шаг 8.3).
- Метасимволы `\d` (цифра) и `\w` (буква) — расширения PCRE (`grep -P`), в базовых и расширенных регулярках их нет; пользуйся `[0-9]` и `[[:alnum:]]`.
- Готовые классы: `[[:digit:]]`, `[[:space:]]`, `[[:upper:]]` — удобнее и переносимее.
- Тестировать регулярки можно в браузере на сайте `regex101.com`.

### deep Если не получилось
- **Ничего не найдено** — проверь регистр и пробелы; ищи по кусочкам, добавляя шаблон постепенно.
- **`grep: Unmatched ( or \(`** — не закрыта скобка (или в BRE забыт `\`).

## 8.2 grep | short: grep | est: ~30 мин
### intro
**Слова шага:** `grep`, *ключи* `-i -v -c -n -o -w -E -r -A -B -C -l -q`.

**`grep шаблон файл`** печатает строки, где шаблон найден. Самая нужная команда для работы с логами. Ключи:

| Ключ | Что делает |
|---|---|
| `-i` | не различать регистр |
| `-v` | вывести строки, где шаблона **нет** |
| `-c` | вместо строк — их **количество** |
| `-n` | показать номера строк |
| `-o` | печатать только совпавшую часть |
| `-w` | искать целое слово |
| `-E` | расширенные регулярки |
| `-r` | искать рекурсивно по папкам |
| `-l` | только имена файлов, где есть совпадения |
| `-A N`, `-B N`, `-C N` | показать N строк после, до, вокруг совпадения |
| `-q` | молча: только код (0 — найдено) |

```bash run
cd /work/coffeeops
grep -c ERROR logs/app.log
grep -n ERROR logs/app.log | head -n 3
grep -v INFO logs/app.log | head -n 3
grep -i 'LATTE' orders/2026-10-01.csv
grep -o 'id=[0-9]*' logs/app.log | head -n 3
grep -w 'tea' orders/2026-10-01.csv
```

Контекст вокруг найденного — незаменим, когда ищешь причину ошибки:

```bash run
grep -n -B 1 -A 1 ERROR logs/app.log | head -n 8
```

Рекурсивный поиск по всему проекту и список файлов:

```bash run
grep -rl 'set -euo pipefail' bin lib | sort
grep -rn --include='*.sh' 'die "' bin | head -n 3
```

Несколько шаблонов и шаблон из переменной (в кавычках!):

```bash run
level="WARN"
grep -E "$level|ERROR" logs/app.log | wc -l
grep -e ERROR -e WARN logs/app.log | wc -l
```

### result
```out auto
```

### why
`grep` — основной инструмент диагностики: найти строку, посчитать, показать контекст. Его код возврата (0 — нашёл, 1 — не нашёл) делает его удобным условием в `if` и скриптах.

### deep Как ещё можно
- `grep -F 'a.b'` — искать **буквально** (без регулярок): безопасно для строк со спецсимволами.
- `grep -P` — регулярки в стиле Perl (`\d`, `\w`) есть только в GNU grep; в macOS его нет.
- `zgrep` — поиск в сжатых `.gz` файлах (удобно для архивов логов).
- `grep` вернёт код `1`, если ничего не найдено: при `set -e` это останавливает скрипт, поэтому пиши `grep … || true`, если отсутствие совпадений — норма.

### deep Если не получилось
- **`grep: Binary file matches`** — файл похож на бинарный; добавь `-a`.
- **Совпадений слишком много** — добавь `-w` (целое слово) или `^`/`$`.

- Что вернёт `grep` в `$?`, если ничего не найдено, и чем это опасно при `set -e`?

## 8.3 sed | short: sed | est: ~30 мин
### intro
**Слова шага:** `sed`, *команда `s`*, *адрес*, `-n` и `p`, `d`, `-i`, *группа* `\1`.

**`sed`** — «потоковый редактор»: читает текст построчно, применяет к каждой строке команды и печатает результат. Главная команда — замена `s`:

```text
sed 's/что/на что/флаги' файл
```

```bash run
cd /work/coffeeops
echo "latte, latte, latte" | sed 's/latte/tea/'
echo "latte, latte, latte" | sed 's/latte/tea/g'
echo "latte, latte, latte" | sed 's/latte/tea/2'
echo "Latte" | sed 's/latte/tea/I'
echo "path/to/file" | sed 's|/|::|g'
```

**Разбор.** Флаги: `g` — все вхождения в строке (а не только первое), число — только N-е, `I` — без учёта регистра. Разделителем может быть любой символ (`|` вместо `/`): удобно, когда в тексте есть слэши.

**Адреса** ограничивают, к каким строкам применять команду:

```bash run
sed -n '2,4p' logs/app.log
sed -n '/ERROR/p' logs/app.log | head -n 2
sed '/INFO/d' logs/app.log | head -n 3
sed -n '$p' logs/app.log
sed '1d' orders/2026-10-01.csv | head -n 2
```

`-n` отключает автоматическую печать каждой строки, `p` печатает выбранную; `2,4` — строки со 2-й по 4-ю; `/ERROR/` — строки, где есть шаблон; `d` — удалить строку; `$` — последняя строка.

**Группы и ссылки.** В режиме `-E` скобки запоминают найденное, а `\1`, `\2` вставляют его:

```bash run
echo "2026-10-01" | sed -E 's/([0-9]{4})-([0-9]{2})-([0-9]{2})/\3.\2.\1/'
echo "id=105" | sed -E 's/id=([0-9]+)/номер \1/'
grep ERROR logs/app.log | head -n 2 | sed -E 's/^([0-9-]+) ([0-9:]+) .* (id=[0-9]+)$/\1 \2 \3/'
```

**Правка файла «на месте»** — ключ `-i`. Всегда делай копию!

```bash run
cp orders/2026-10-01.csv tmp/o1.csv
sed -i.bak 's/latte/LATTE/' tmp/o1.csv
ls tmp | grep o1
diff tmp/o1.csv.bak tmp/o1.csv | head -n 4
```

`-i.bak` — править файл и сохранить прежнюю версию под именем `o1.csv.bak`.

### result
```out auto
```

### why
`sed` — это «найти и заменить» для скриптов: поправить конфиг, вырезать строки, переформатировать даты. А `-i` меняет файл прямо на диске, поэтому им пользуются осторожно.

### deep Как ещё можно
- Несколько команд: `sed -e 's/a/b/' -e 's/c/d/'` или через `;`.
- Вставить строку: `sed '2i\новая строка'` (перед второй), `a\` — после, `c\` — заменить строку.
- Для многострочных правок удобнее `awk` или отдельная программа.
- Подставлять переменные в `sed` лучше в двойных кавычках (`sed "s/x/$var/"`), но тогда символы `/` и `&` в значении сломают команду — экранируй или бери другой разделитель.

### deep Если не получилось
- **`sed: -e expression #1, char N: unterminated 's' command`** — не закрыт `s///` или в тексте есть разделитель; смени разделитель.
- **Файл не изменился** — без `-i` `sed` лишь печатает результат, сам файл не трогает.

## 8.4 awk | short: awk | est: ~40 мин
### intro
**Слова шага:** `awk`, *запись*, *поле*, `$1`, `$0`, `NR`, `NF`, `BEGIN`, `END`, *ассоциативный массив*, `printf`.

**`awk`** читает текст **записями** (по умолчанию строка = запись), делит каждую на **поля** (по умолчанию по пробелам) и выполняет для неё действия. Программа — это набор пар «условие `{действие}`».

```bash run
cd /work/coffeeops
head -n 3 logs/app.log | awk '{ print $3, $4 }'
head -n 2 logs/app.log | awk '{ print "строка", NR, "полей", NF, "последнее:", $NF }'
```

`$1`, `$2`, … — поля; `$0` — вся строка; `NR` — номер записи; `NF` — число полей; `$NF` — последнее поле. Условие `NR > 1` ниже — «пропусти первую строку», то есть заголовок CSV. Запятая в `print` ставит между значениями пробел.

**Разделитель полей** — ключ `-F`:

```bash run
awk -F, 'NR > 1 { print $2 }' orders/2026-10-01.csv | head -n 3
awk -F, 'NR > 1 && $3 >= 3 { print $1, $2, $3 }' orders/2026-10-01.csv
awk '$3 == "ERROR"' logs/app.log | head -n 2
awk '/payment/ { n++ } END { print "платежей:", n }' logs/app.log
```

Слева от `{ … }` — **условие**: сравнение, шаблон `/regex/`, номер строки; если его нет — действие выполняется для всех строк. Если нет действия — строка просто печатается.

**`BEGIN` и `END`** выполняются один раз до и после всех записей — для заголовков и итогов:

```bash run
awk -F, 'BEGIN { print "ТОВАР\tСУММА" } NR > 1 { s += $3 * $4 } END { print "итого", s }' orders/2026-10-01.csv
```

**Ассоциативные массивы** в `awk` есть всегда (без `declare`) — отсюда «группировка» в одну строку:

```bash run
awk -F, 'FNR > 1 { qty[$2] += $3 } END { for (k in qty) print k, qty[k] }' orders/*.csv | sort
awk '{ n[$3]++ } END { for (k in n) printf "%-6s %d\n", k, n[k] }' logs/app.log | sort
```

**Несколько файлов сразу.** Когда файлов несколько (`orders/*.csv`), заголовок есть у каждого. `NR` считает записи **подряд по всем файлам**, поэтому `NR > 1` пропустит заголовок только первого файла; для «пропустить первую строку каждого файла» нужен **`FNR`** (номер записи внутри текущего файла). В командах выше мы используем `FNR > 1`.

**Форматированный вывод** — `printf` (как в bash), и функции для строк:

```bash run
awk -F, 'FNR > 1 { sum[$2] += $3 * $4 } END { for (k in sum) printf "%-12s %6.2f\n", k, sum[k] }' orders/*.csv | sort
awk '{ print toupper($3), length($4) }' logs/app.log | head -n 2
```

**JSON и `jq` (обзор).** Для JSON `awk` не подходит — есть отдельный инструмент `jq`:

```bash run
echo '{"item":"latte","qty":2,"tags":["hot","milk"]}' | jq -r '.item'
echo '{"item":"latte","qty":2,"tags":["hot","milk"]}' | jq '.qty * 180'
echo '[{"item":"tea","qty":1},{"item":"latte","qty":3}]' | jq -r '.[] | "\(.item): \(.qty)"'
```

### result
```out auto
```

### why
`awk` — «электронная таблица для командной строки»: суммы, группировки, фильтры по столбцам одной строкой. Там, где `cut`/`sort`/`uniq` уже тесно, он делает всё сразу. А `jq` — то же для JSON, который встречается в ответах API.

### deep Как ещё можно
- Передать переменную bash в `awk`: `awk -v lim="$limit" '$3 > lim'`; ставить `$var` внутрь программы в кавычках не стоит.
- `awk` — полноценный язык: есть `if`, циклы, функции (`function f(x) { … }`), `split`, `substr`, `gsub`.
- Другой разделитель вывода: `awk 'BEGIN { OFS="," } { print $1, $2 }'`.
- Разные реализации: в Alpine/Debian мы используем GNU awk (`gawk`), на Mac — BSD awk; для простых программ разницы нет.

### deep Если не получилось
- **Одно из полей пустое** — разделитель не тот (`-F,` для CSV, пробел для лога).
- **`awk: syntax error`** — программа в одинарных кавычках, внутри не должно быть одинарных; используй `"` внутри и `\047`/`-v` для остального.
- **`jq: command not found`** — образ собран без `jq`; пересобери образ (шаг 1.2).

## 8.5 🔨 Сломать → починить: sed -i, жадность, спецсимволы | short: Сломать → починить | est: ~25 мин
### intro
:::trap Сломать → починить
Три ловушки при работе с текстом.
:::

**Ошибка 1 — жадная регулярка.** `.*` захватывает «как можно больше»:

```bash run
cd /work/coffeeops
echo '<b>latte</b> и <b>tea</b>' | sed 's/<.*>//'
echo '<b>latte</b> и <b>tea</b>' | sed 's/<[^>]*>//g'
```

В первом случае `.*` дотянулась до **последнего** `>`, и вся строка исчезла. **Почини:** вместо «любое число любых символов» пиши «любое число символов, кроме закрывающего»: `[^>]*`.

**Ошибка 2 — точка в шаблоне.** `.` — любой символ:

```bash run
printf 'id=101\nid=1x1\nid=1.1\n' | grep 'id=1.1'
echo "--- буквально:"
printf 'id=101\nid=1x1\nid=1.1\n' | grep -F 'id=1.1'
```

Хотели найти `id=1.1`, а подошли все три. **Почини:** `grep -F` (буквально) или `\.`.

**Ошибка 3 — шаблон без кавычек.** Оболочка видит `|` раньше, чем `grep`:

```bash run
grep ERROR|WARN logs/app.log
echo "код: $?"
grep -E 'ERROR|WARN' logs/app.log | wc -l
```

Без кавычек `|` разорвал команду на две: `grep ERROR` (без файла — читает ввод с клавиатуры!) и команду `WARN`. **Правило:** шаблоны всегда в одинарных кавычках.

**Отличие GNU и macOS: `sed -i`.** В нашем контейнере (GNU sed) `-i` работает так, как мы писали. На macOS стоит BSD-вариант, и **та же команда падает**: у ключа `-i` там обязателен аргумент (суффикс резервной копии). Показываем вывод вручную, потому что запускалось не в контейнере:

```bash
sed -i 's/latte/tea/' file.csv          # на macOS (BSD sed):
# sed: 1: "file.csv": extra characters at the end of f command   (или: invalid command code f)
sed -i '' 's/latte/tea/' file.csv       # macOS: пустой суффикс = без копии
sed -i.bak 's/latte/tea/' file.csv      # работает и там, и там (с копией)
```

Безопасный и переносимый вариант — всегда `-i.bak` (без пробела между `-i` и суффиксом) либо работать через временный файл: `sed … файл > файл.new && mv файл.new файл`.

### result
```out auto
```

### why
Эти ошибки не останавливают скрипт, а дают неверные данные. Одинарные кавычки вокруг шаблонов, `grep -F` для буквального поиска и `[^…]*` вместо `.*` — три привычки, которые их предотвращают. А знание про `sed -i` сэкономит время, когда скрипт перенесут с Linux на Mac и наоборот.

### deep Как ещё можно
- Ленивые квантификаторы (`.*?`) есть только в PCRE (`grep -P`), в `sed` и `grep -E` их нет — поэтому используем `[^…]*`.
- GNU и BSD различаются и в других мелочах: `grep -P` (только GNU), `ls --color` / `ls -G`, `date -d` (только GNU), `sed -r` (GNU) / `sed -E` (везде). Пиши переносимо там, где скрипт может запускаться на Mac.

### deep Если не получилось
- **В блоке 3 терминал «завис»** — `grep ERROR` ждёт ввод с клавиатуры (из-за потерянного файла). Нажми [[Ctrl]]+[[D]] или [[Ctrl]]+[[C]]. В нашем стенде ввод пустой, поэтому он сразу завершился.

## 8.6 Проект: отчёты по журналу двумя способами | short: Проект: отчёты по логу | est: ~35 мин
### intro
**Слова шага:** *отчёт*, *два способа*, *сверка результатов*.

Сделаем три отчёта по `logs/app.log`: (1) число записей по уровням, (2) топ событий, (3) ошибки по часам. Каждый — **двумя способами**: через `awk` и на чистом bash. Затем проверим, что результаты **одинаковы**.

```bash run
cd /work/coffeeops
cat > bin/logreport.sh <<'EOF'
#!/usr/bin/env bash
# Отчёты по журналу. Использование: logreport.sh [-m awk|bash] [ФАЙЛ]
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
# shellcheck source=../lib/common.sh
source "$ROOT/lib/common.sh"

usage() { echo "Использование: logreport.sh [-m awk|bash] [ФАЙЛ]"; }

method="awk"
while getopts ":m:h" opt; do
  case "$opt" in
    m) method="$OPTARG" ;;
    h) usage; exit 0 ;;
    *) usage >&2; exit 2 ;;
  esac
done
shift $((OPTIND - 1))
file="${1:-$ROOT/logs/app.log}"

[[ "$method" == awk || "$method" == bash ]] || die "метод: awk или bash, а не '$method'" 2
[[ -f "$file" ]] || die "нет файла '$file'" 2

report_awk() {
  echo "== по уровням"
  awk '{ n[$3]++ } END { for (k in n) printf "%-6s %d\n", k, n[k] }' "$file" | sort
  echo "== топ событий"
  awk '{ n[$4]++ } END { for (k in n) printf "%-14s %d\n", k, n[k] }' "$file" | sort -k2,2nr -k1,1
  echo "== ошибки по часам"
  awk '$3 == "ERROR" { n[substr($2, 1, 2)]++ } END { for (k in n) printf "%s:00 %d\n", k, n[k] }' "$file" | sort
}

report_bash() {
  local time level event
  declare -A by_level=() by_event=() err_hour=()
  while read -r _ time level event _; do
    by_level[$level]=$(( ${by_level[$level]:-0} + 1 ))
    by_event[$event]=$(( ${by_event[$event]:-0} + 1 ))
    if [[ "$level" == ERROR ]]; then
      err_hour[${time:0:2}]=$(( ${err_hour[${time:0:2}]:-0} + 1 ))
    fi
  done < "$file"

  local k
  echo "== по уровням"
  for k in "${!by_level[@]}"; do printf '%-6s %d\n' "$k" "${by_level[$k]}"; done | sort
  echo "== топ событий"
  for k in "${!by_event[@]}"; do printf '%-14s %d\n' "$k" "${by_event[$k]}"; done | sort -k2,2nr -k1,1
  echo "== ошибки по часам"
  for k in "${!err_hour[@]}"; do printf '%s:00 %d\n' "$k" "${err_hour[$k]}"; done | sort
}

"report_$method"
EOF
chmod +x bin/logreport.sh
./bin/logreport.sh
echo "=== сверка двух способов:"
diff <(./bin/logreport.sh -m awk) <(./bin/logreport.sh -m bash) && echo "результаты одинаковы"
./bin/logreport.sh -m perl
echo "код: $?"
shellcheck bin/logreport.sh && echo "shellcheck: чисто"
```

**По частям.** Две функции — два способа; `"report_$method"` вызывает функцию по имени (`report_awk` или `report_bash`); в варианте на bash чтение идёт `while read -r _ time level event _` (поля: дата — пропуск, время, уровень, событие, остаток — пропуск); счётчики — ассоциативные массивы; `sort` нужен только для устойчивого порядка вывода. Команда `diff <(…) <(…)` сравнивает вывод двух запусков.

### result
```out auto
```

### why
Один и тот же результат двумя способами — лучший тест: если они совпали, ошибка маловероятна. И заодно понятно, когда что выбирать: `awk` короче и быстрее на больших файлах, bash проще встроить в логику скрипта.

### deep Как ещё можно
- Фильтр по времени: `awk '$2 >= "09:00:00" && $2 < "10:00:00"'` (время в формате ЧЧ:ММ:СС сравнивается как строка правильно).
- Подсчёт «медленных» событий (`printer-slow`) и порог ошибок для оповещения — основа мониторинга: в сессии 9 это пригодится для проверки состояния.

### deep Если не получилось
- **`diff` показывает отличия** — проверь формат `printf` в обоих способах (ширина колонок) и порядок сортировки.
- **Пустые отчёты** — в журнале нет строк нужного формата (`bash seed.sh` создаёт его заново).
