## 4.1 Цикл for | short: for | est: ~30 мин
### intro
**Слова шага:** *цикл*, *итерация*, `for … in`, *раскрытие шаблона*, `{1..5}`, `seq`.

**Цикл** повторяет команды для каждого элемента списка. Самая частая форма — `for`:

```text
for переменная in список; do
  команды
done
```

Переменная по очереди принимает каждое значение списка. Что может быть списком:

```bash run
cd /work/coffeeops
for item in latte espresso tea; do
  echo "товар: $item"
done
for n in {1..3}; do
  echo "номер $n"
done
for f in orders/*.csv; do
  echo "файл: $f ($(wc -l < "$f") строк)"
done
```

**Что здесь.** Список можно задать словами; диапазоном `{1..3}` (или `{a..e}`, `{0..10..2}` — с шагом 2; это *brace expansion*, его делает оболочка); шаблоном файлов `orders/*.csv` — оболочка заменит его на список подходящих файлов, и цикл пройдёт по каждому. Команда `wc -l < "$f"` считает строки (`<` — «возьми ввод из файла»).

Есть и «C-стиль» — когда нужен счётчик с условием:

```bash run
for ((i = 1; i <= 3; i++)); do
  echo "итерация $i"
done
seq 1 2 7
```

`seq первое шаг последнее` печатает числа; его используют, когда границы лежат в переменных.

**Главная ловушка — пробелы в именах.** Если файл называется `iced latte.csv`, то:

```bash run
mkdir -p tmp-for
touch "tmp-for/iced latte.csv" tmp-for/tea.csv
echo "--- опасно: цикл по выводу ls"
for f in $(ls tmp-for); do echo "[$f]"; done
echo "--- правильно: шаблон и кавычки"
for f in tmp-for/*.csv; do echo "[$f]"; done
rm -r tmp-for
```

### result
```out auto
```

`for f in $(ls …)` разрезал имя по пробелу на два «файла», а шаблон `tmp-for/*.csv` сохранил имя целым. **Никогда не перебирай файлы через `$(ls …)`**: пользуйся шаблоном и ставь переменную в кавычки.

### why
Цикл — это способ обработать «все файлы», «все строки», «все серверы» одной записью. А ловушка с `$(ls)` — самая частая причина, по которой скрипт «ломается на файле с пробелом» (и иногда — удаляет не то).

### deep Как ещё можно
- Если шаблон ничего не нашёл (`*.xml` без файлов), цикл выполнится один раз со строкой `*.xml` — в скриптах это проверяют: `[[ -e "$f" ]] || continue`, либо включают `shopt -s nullglob` (тогда пустой шаблон даёт пустой список).
- Перебор аргументов скрипта: `for a in "$@"; do …; done` (в кавычках!).
- Выйти из цикла: `break`; пропустить итерацию: `continue`.

### deep Если не получилось
- **`syntax error near unexpected token 'done'`** — пропущен `do` или перевод строки/`;` перед ним.
- **Файл с пробелом «распался»** — забыты кавычки вокруг `"$f"`.

## 4.2 while, until и чтение файла по строкам | short: while и чтение файла | est: ~30 мин
### intro
**Слова шага:** `while`, `until`, `break`, `continue`, `while read`, `IFS`.

`while` повторяет, **пока условие истинно** (код 0); `until` — пока **ложно**:

```bash run
n=1
while (( n <= 3 )); do
  echo "while: $n"
  ((n++))
done
until (( n == 0 )); do
  ((n--))
  echo "until: n=$n"
done
```

**`break` и `continue`:** первый выходит из цикла, второй пропускает остаток текущей итерации:

```bash run
for n in 1 2 3 4 5 6; do
  (( n % 2 == 0 )) && continue
  (( n > 5 )) && break
  echo "нечётное: $n"
done
```

**Читать файл построчно** — самый полезный приём `while`:

```bash run
cd /work/coffeeops
while IFS= read -r line; do
  echo "строка: $line"
done < <(head -n 3 orders/2026-10-01.csv)
```

**Разбор.** `read -r line` читает очередную строку; когда строки кончаются, `read` возвращает «ложь» и цикл заканчивается. `IFS=` (перед `read`, на одну команду) отключает обрезку пробелов по краям строки — без него потеряются отступы. `< файл` — данные берутся из файла; `< <(команда)` — из вывода команды (*подстановка процесса*, подробнее в сессии 6).

Если в строке несколько полей, `read` разделит их по символу `IFS`:

```bash run
while IFS=, read -r time item qty price; do
  [[ "$time" == "time" ]] && continue
  echo "$item: $qty шт. по $price руб."
done < <(head -n 4 orders/2026-10-01.csv)
```

`IFS=,` — разделитель запятая; четыре переменные получают четыре поля; строку-заголовок пропускаем через `continue`.

### result
```out auto
```

### why
Почти каждый скрипт обработки данных — это «прочитать файл, для каждой строки что-то сделать». `while IFS= read -r line` — безопасный шаблон для этого, он не портит пробелы и слэши.

### deep Как ещё можно
- `while read … done < файл` читает файл. А вариант `команда | while read …` запускает цикл в **подпроцессе**, и переменные, изменённые внутри, после цикла пропадают. Поэтому мы используем `< <(команда)`.
- Бесконечный цикл: `while true; do …; sleep 1; done` — выйти по `break` или Ctrl+C.
- Для CSV с кавычками и запятыми внутри полей `read` не подходит — нужен `awk` или специальные утилиты.

### deep Если не получилось
- **Цикл не выводит ничего** — файл пуст или путь неверный.
- **Переменная после цикла пуста** — цикл выполнился в подпроцессе (из-за `|`). Используй `< <(…)` или `< файл`.

## 4.3 Коды завершения и строгий режим | short: Коды и строгий режим | est: ~35 мин
### intro
**Слова шага:** `$?`, `exit`, *код завершения*, `set -e`, `set -u`, `set -o pipefail`.

Каждая команда по завершении возвращает число — **код завершения**. `0` — успех, всё остальное — ошибка. Прочитать код последней команды можно через `$?`:

```bash run
true
echo "true: $?"
false
echo "false: $?"
ls /нет-такой-папки
echo "ls: $?"
nonexistent-command
echo "нет команды: $?"
```

Принятые коды:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | общая ошибка |
| `2` | неверное использование (например, не хватает аргументов) |
| `126` | файл найден, но не исполняемый |
| `127` | команда не найдена |
| `130` | прервано Ctrl+C (128 + номер сигнала 2) |

Свой скрипт завершается командой `exit N`; без неё — кодом **последней выполненной команды**. Коды работают с `&&` и `||` (шаг 3.3): `mkdir x && cd x`, `ping … || echo "недоступен"`.

**Строгий режим.** По умолчанию bash **продолжает** работу после ошибки. Это опасно: скрипт может «успешно» дойти до конца, сломав всё по пути. Три настройки меняют это:

| Настройка | Что делает |
|---|---|
| `set -e` | завершить скрипт, если команда вернула ошибку |
| `set -u` | считать ошибкой обращение к необъявленной переменной |
| `set -o pipefail` | в конвейере `a \| b` ошибка **любой** команды — ошибка всего конвейера |

Часто пишут все три вместе: `set -euo pipefail`. Сравним поведение (каждый скрипт запускаем в отдельном процессе):

```bash run
cd /work/coffeeops
cat > bin/nostrict.sh <<'EOF'
#!/usr/bin/env bash
cp нет-такого-файла.txt /tmp/копия.txt
echo "готово, всё прекрасно"
EOF
cat > bin/strict.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
cp нет-такого-файла.txt /tmp/копия.txt
echo "готово, всё прекрасно"
EOF
chmod +x bin/nostrict.sh bin/strict.sh
./bin/nostrict.sh
echo "код: $?"
./bin/strict.sh
echo "код: $?"
```

Без `set -e` скрипт сообщил «готово» после ошибки. С ним — остановился на первой неудаче. Теперь `-u`:

```bash run
bash -c 'echo "значение: [$undefined_var]"'
bash -c 'set -u; echo "значение: [$undefined_var]"'
```

И `pipefail`: конвейер возвращает код **последней** команды, поэтому ошибка в начале теряется:

```bash run
bash -c 'false | cat; echo "без pipefail: $?"'
bash -c 'set -o pipefail; false | cat; echo "с pipefail: $?"'
```

### result
```out auto
```

### why
Без строгого режима сломанный скрипт выглядит успешным: бэкап не сделан, а `exit 0`. Строгий режим превращает тихие поломки в громкие. Коды завершения — это «язык», на котором скрипты общаются между собой, с `cron`, с CI и с деплоем.

### deep Как ещё можно
- `set -e` не срабатывает внутри условий: в `if cmd; then` и в `cmd || …` ошибка `cmd` ожидаема, скрипт не остановится. Это задумано, но иногда удивляет.
- Если ошибка допустима, укажи это явно: `grep -q x файл || true` — «ошибка не страшна».
- Не стоит включать `-e` в скриптах, которые подключают через `source` в твою интерактивную оболочку: при первой ошибке закроется весь терминал.
- Эквиваленты: `set -e` ≡ `set -o errexit`, `set -u` ≡ `set -o nounset`.

### deep Если не получилось
- **Скрипт останавливается «без причины»** — одна из команд вернула ненулевой код (например, `grep` ничего не нашёл — это код 1). Найди её (`bash -x скрипт` покажет каждую команду) и разреши ошибку (`|| true`) или обработай.
- **`unbound variable`** — используется переменная без значения; задай умолчание `${var:-}` или проверь опечатку.

## 4.4 trap: прибираем за собой | short: trap | est: ~30 мин
### intro
**Слова шага:** `trap`, *сигнал*, `EXIT`, `ERR`, `INT`, `TERM`, `mktemp`.

Скрипты создают временные файлы. Если скрипт упал или его прервали, мусор останется. **`trap`** — «ловушка»: команда, которая выполнится при событии. Основные события:

| Событие | Когда |
|---|---|
| `EXIT` | скрипт завершается **любым** способом (конец, `exit`, ошибка при `set -e`) |
| `ERR` | любая команда вернула ошибку |
| `INT` | нажали Ctrl+C |
| `TERM` | попросили завершиться (`kill` без ключей) |

```bash run
cd /work/coffeeops
cat > bin/clean.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
tmp=$(mktemp)
trap 'echo "убираю $tmp"; rm -f "$tmp"' EXIT
echo "данные" > "$tmp"
echo "работаю с $(wc -c < "$tmp") байтами во временном файле"
false
echo "до сюда не дойдём"
EOF
chmod +x bin/clean.sh
./bin/clean.sh
echo "код: $?"
```

**Разбор.** `mktemp` создаёт временный файл с уникальным именем (в `/tmp`) и печатает путь; `trap 'команды' EXIT` запоминает, что сделать при выходе (в одинарных кавычках — чтобы `$tmp` раскрылся **в момент срабатывания**, а не сразу); `false` вызывает ошибку, `set -e` останавливает скрипт, и перед выходом срабатывает `EXIT`.

**Сигналы.** `Ctrl+C` посылает процессу сигнал `INT`. Поймаем остановку по `TERM` (так же работает и `INT`):

```bash run
cat > bin/slow.sh <<'EOF'
#!/usr/bin/env bash
tmp=$(mktemp)
cleanup() { echo "поймали сигнал, убираю $tmp"; rm -f "$tmp"; exit 143; }
trap cleanup INT TERM
echo "работаю..."
sleep 30
EOF
chmod +x bin/slow.sh
./bin/slow.sh &
pid=$!
sleep 1
kill -TERM "$pid"
wait "$pid"
echo "код завершения: $?"
```

Здесь мы послали `TERM` другим процессом: `./bin/slow.sh &` запускает скрипт **в фоне**, `$!` — номер его процесса, `kill -TERM` посылает сигнал, `wait` дожидается и забирает код. В обычной работе всё проще: запусти `./bin/slow.sh` и нажми Ctrl+C — увидишь то же сообщение. Код `143` в нашем примере задан строкой `exit 143` (так принято для `TERM`: 128 + 15); если ловушки нет и скрипт прерван Ctrl+C, код будет `130` (128 + 2).

### result
```out auto
```

### why
`trap … EXIT` — гарантия, что временные файлы, блокировки и «полузаписанные» результаты исчезнут при любом завершении. Без него ночной скрипт, упавший на середине, оставит мусор и сломает следующий запуск.

### deep Как ещё можно
- `trap - EXIT` — снять ловушку.
- `trap 'echo "ошибка в строке $LINENO"' ERR` — печатать номер строки, где случилась ошибка (с `set -e`).
- Сигнал `KILL` (`kill -9`) поймать **нельзя**: процесс убивается мгновенно, поэтому `kill -9` — крайняя мера.
- Ловушку удобно оформлять функцией (`cleanup`), как в примере; функции — в сессии 5.

### deep Если не получилось
- **Ловушка не срабатывает при Ctrl+C** — сигнал `INT` ловится только если указан в `trap`; если скрипт запущен в фоне (`&`) в неинтерактивной оболочке, `INT` игнорируется (поэтому в примере `TERM`).
- **В `trap` пустое значение переменной** — команда в двойных кавычках раскрылась слишком рано; бери одинарные.

## 4.5 🔨 Сломать → починить: «успешный» провал | short: Сломать → починить | est: ~20 мин
### intro
:::trap Сломать → починить
Скрипт-«бэкап» сообщает об успехе, хотя бэкапа нет. Найди причину и почини (подсказка: шаг 4.3).
:::

```bash run
cd /work/coffeeops
cat > bin/backup-broken.sh <<'EOF'
#!/usr/bin/env bash
# Делает копию заказов в backup/
mkdir -p backup
cp orders/2026-10-09.csv backup/
tar -czf backup/orders.tgz orders/not-exist
echo "Бэкап готов!"
EOF
chmod +x bin/backup-broken.sh
./bin/backup-broken.sh
echo "код: $?"
ls backup
```

Скрипт напечатал «Бэкап готов!» и вернул `0`, хотя обе команды упали. **Почини:** добавь вторую строку `set -euo pipefail`, а затем сделай так, чтобы временный результат не оставался при неудаче.

```bash run
cat > bin/backup.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
mkdir -p backup
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT
tar -czf "$tmp" orders
mv "$tmp" backup/orders.tgz
echo "Бэкап готов: $(ls -l backup/orders.tgz | awk '{print $5}') байт"
EOF
chmod +x bin/backup.sh
./bin/backup.sh
echo "код: $?"
tar -tzf backup/orders.tgz
```

Идея: архив собирается во временный файл, и только когда всё получилось, переезжает на своё место (`mv`). Если `tar` упадёт, старый бэкап не повреждён.

### result
```out auto
```

### why
Два приёма — строгий режим и «сначала во временный файл, потом на место» — защищают от самого неприятного сценария: бэкап, который не сделан, но считается сделанным.

### deep Как ещё можно
- Можно проверять результат явно: `[[ -s backup/orders.tgz ]] || exit 1` (файл не пустой).
- Ту же идею «собрать во временном месте, потом переименовать» применяют для конфигов и деплоя (сессия 9).

### deep Если не получилось
- **`tar: orders/not-exist: Cannot stat`** — это и есть ожидаемая ошибка в сломанной версии.
- **Старый `backup/orders.tgz` остался** — удали и повтори (`rm backup/orders.tgz`).

## 4.6 Проект: итоги по заказам | short: stats.sh | est: ~30 мин
### intro
**Слова шага:** *цикл по файлам*, `mktemp`, `trap`, *строгий режим*, `awk` как калькулятор.

Скрипт `bin/stats.sh` обходит все `orders/*.csv`, считает заказы и выручку по дням и показывает лучший день. Для суммы используем `awk` как калькулятор (его подробно разберём в сессии 8): `awk -F, 'NR > 1 { s += $3 * $4 } END { print s + 0 }'` — «суммируй произведение полей 3 и 4 во всех строках, кроме первой (заголовка)».

```bash run
cd /work/coffeeops
cat > bin/stats.sh <<'EOF'
#!/usr/bin/env bash
# Итоги по файлам заказов. Использование: stats.sh [ПАПКА]
set -euo pipefail

dir="${1:-orders}"
if [[ ! -d "$dir" ]]; then
  echo "Ошибка: нет папки '$dir'" >&2
  exit 2
fi

tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT

total_all=0
for f in "$dir"/*.csv; do
  [[ -e "$f" ]] || continue
  rows=$(( $(wc -l < "$f") - 1 ))
  sum=$(awk -F, 'NR > 1 { s += $3 * $4 } END { print s + 0 }' "$f")
  echo "$(basename "$f"): заказов $rows, выручка $sum руб."
  echo "$sum $(basename "$f")" >> "$tmp"
  total_all=$((total_all + sum))
done

echo "ИТОГО: $total_all руб."
echo "Лучший день: $(sort -rn "$tmp" | head -n 1 | cut -d' ' -f2)"
EOF
chmod +x bin/stats.sh
./bin/stats.sh
echo "код: $?"
./bin/stats.sh нет-папки
echo "код: $?"
```

**По частям.** `set -euo pipefail` — строгий режим; проверка папки — «сначала проверить»; `>&2` отправляет сообщение в канал ошибок (`stderr`; подробно — сессия 6); `mktemp` и `trap … EXIT` — временный файл и уборка; `for f in "$dir"/*.csv` — цикл по шаблону с кавычками; `[[ -e "$f" ]] || continue` — защита от пустого шаблона; `sort -rn | head -n 1` — наибольшая сумма; `cut -d' ' -f2` — вторая колонка (имя файла).

Проверим уборку: пока скрипт работает, временный файл существует, а после — нет:

```bash run
ls /tmp | grep -c '^tmp\.' || true
```


Последняя команда показала `0` — временных файлов не осталось. Заметь ещё: у двух дней выручка одинаковая (3520), поэтому «лучшим» названо `2026-10-02.csv`: при равных суммах `sort -rn` ставит выше файл, чей номер больше. Такие совпадения — норма, на них скрипт не должен падать.

### why
Это первый «настоящий» инструмент проекта: проверка входа, строгий режим, цикл, уборка, понятный итог. По такой структуре писать скрипты проще, чем изобретать каждый раз заново.

- Вывести выручку по товарам — это сессия 7 (ассоциативные массивы) и сессия 8 (awk).
